01_SYSTEM/01_AUDITORIA_R6_VS_GEOMETRA_V3.txt
==========================================================================================
ABRXOS · AUDITORÍA R6 VS GEOMETRA V3

CONCLUSIÓN
R6 SÍ sirve como canon de producción para el sistema, pero Geometra V3 todavía no explota visualmente todas sus capacidades. La compatibilidad de datos es buena porque V3 conserva campos desconocidos y normaliza pieces[]; la compatibilidad de UI es parcial y requiere patch V3.1.

R6 QUE YA ENCAJA SIN CAMBIAR KERNEL
- stage BETA/ALFA/OMEGA.
- workflowStatus PENDIENTE/REVISADO/HACIENDO/LISTO/PROGRAMADO/PUBLICADO.
- schedule.
- sourceRanges como tiempo master.
- timeline start/end como tiempo editorial.
- T1–T9.
- VO sin sourceRange falso.
- staticProduction para carruseles.
- renderer packs.
- Cutter boundary por ID/type/source/sourceRanges.
- campos extra en piezas y eventos.
- custom XR/SFX por datos/extension/fallback.

R6 QUE V3 PUEDE CONSERVAR PERO NO REPRESENTA AÚN DE FORMA ESPECIALIZADA
1. xrFamily semánticas R6: COMIC_INFO, COMIC_CC, TYPO, PHOTOS, OBJECTS, PHOTO_OBJECT, NO_XR.
   V3 no debe mapearlas ciegamente a XR00–XR09. Debe reconocerlas como catálogo R6 o fallback custom.
2. CINE en T5 con type=cine.
   El runtime actual puede conservarlo, pero necesita inspector CINE específico.
3. editProfile.
   Debe mostrar código + nombre comercial.
4. Visual Asset R6.
   Debe mostrar contextAndDetail, whatIsVisible, whyItMatchesSpeech, prompt, search, placement y status.
5. Caption Groups R6.
   Es el punto de incompatibilidad funcional más importante: V3 inicial segmentó captions cortos; R6 exige groups semánticos 8–15 y displayCues internos.
6. productionChecklist.
   Puede persistir hoy, pero todavía no tiene UI completa.

KANBAN
LIENZO V3: drag/drop ya cambia workflowStatus.
GEOMETRA V3 app: columnas existen, pero falta drag/drop y POST /api/update_piece. Esto es patch P0 y NO exige schema nuevo.

R6.1 AÑADE
- sourceAlignment como etapa previa a sourceRanges cuando hay microtrims pendientes;
- contrato VO_ADDED por placement;
- source correction explícita;
- projection contract para que el Lienzo sepa qué inspector abrir;
- especificación de ghost/unresolved timing para revisión;
- test case real: nuevo intro Amanda.

ABRXOS · PIPELINE COMPLETO DEL PROGRAMA

1. INPUT
- plan editorial natural;
- transcript SRT/TXT;
- ficha Beta/Alfa JSON;
- HTML Story Editor/Lienzo;
- Project Config;
- Brand Adapter;
- catálogos XR/SFX/Motion/CINE/Captions.

2. PLAN PARSER
Clasifica cada nodo natural:
SOURCE_SPEECH
VO_ADDED
EDIT_DIRECTION
TITLE_CARD
OPEN_LOOP

3. SOURCE ALIGNMENT
Sólo SOURCE_SPEECH se busca en transcript/master.
Salida:
- parent cue range;
- source literal;
- cueIds;
- start/end si el cue entero coincide;
- microtrim anchors si la frase está dentro del cue;
- timingStatus;
- source corrections.

4. SOURCE QA
No pasar a sourceRanges finales mientras existan microtrims críticos sin resolver.
Opciones:
- word timestamps;
- audio alignment;
- MLX/ASR local;
- revisión humana.

5. ALFA BUILDER
Combina plan + source map + canon + brand:
- parts;
- storyScripts/routes;
- T1 A-roll;
- T6 VO;
- 6 XR si profile XR_FULL y la función lo justifica;
- T3 images/objects;
- T4 motion;
- T5 b-roll/CINE;
- T7 SFX;
- T8 music automation;
- T9 Caption Groups;
- cover/copy;
- productionChecklist;
- QA.

6. GEOMETRA IMPORTER
HTML app-data/seed/editorialData o JSON → normalize_project → abrxos.document.v3.
R6 puede entrar como abrxos.content-project.r6 porque pieces[] es compatible y V3 conserva campos adicionales.

7. LIBRARY
projectId + canonicalId = identidad de actualización.
Mismo canonicalId reemplaza/actualiza la misma ficha, no crea contenido nuevo.

8. COMPILER
Proyecto + selección de fichas + renderer → Lienzo standalone.
Se embebe app-data + catalog snapshot + runtime + renderer.

9. LIENZO
El runtime proyecta el documento:
video → Story + Inspector + Timeline.
carousel → Carousel Workspace.
calendar → schedule.
kanban → workflowStatus.

10. EDICIÓN
Click selecciona; drag real mueve después de threshold. Edición modifica state.project, no DOM como verdad.

11. EXPORT / REIMPORT
Exportar HTML vuelve a escribir app-data actualizado. Puede reimportarse a Geometra por IDs estables.

12. CUTTER
Consume sourceRanges finales. No debe cortar a partir de XR/CINE/SFX/timeline editorial salvo un futuro Cut Override aprobado.

01_SYSTEM/04_ACTUALIZACION_GENERAL_DEL_SISTEMA_R6_1.txt
==========================================================================================
ABRXOS · ACTUALIZACIÓN GENERAL DEL SISTEMA A PARTIR DE R6/R6.1

ANTES
Una ficha rica podía decir XR/SFX pero la frontera entre plan natural, source alignment y timeline final no estaba completamente formalizada.

AHORA
1. PLAN EDITORIAL NATURAL es parseable como nodos tipados.
2. SOURCE SPEECH se alinea antes de crear sourceRanges finales.
3. VO_ADDED tiene placement y duración propia.
4. CINE vive en tracks existentes y no cuenta como XR.
5. XR usa familias semánticas R6 y assets internos explícitos.
6. Motion/SFX/Music son objetos temporales separados.
7. Captions pasan a Caption Groups semánticos R6.
8. productionChecklist y workflowStatus separan avance real de madurez Beta/Alfa/Omega.
9. Lienzo necesita inspectors especializados por tipo de evento.
10. Cutter permanece desacoplado: sourceRanges siguen siendo su contrato base.

CÓMO SE ADAPTA SIN ROMPER
- R6/R6.1 añade campos; V3 preserva campos desconocidos.
- renderer/runtime se actualiza para proyectarlos.
- legacy R5 sigue siendo válido.
- policyVersion permite convivencia de captions legacy/R6.
- sourceAlignment es previo a sourceRanges, no reemplaza Cutter.
- custom/fallback evita que un XR nuevo rompa el Lienzo.

RESULTADO
Geometra deja de ser «un HTML que muestra fichas» y se consolida como compilador/gestor del documento canónico. El Lienzo pasa a ser un editor de decisiones de producción: permite ver, copiar, modificar y calendarizar cada recurso sin convertirse en el motor de media.

ABRXOS R6.1 · SOURCE TRUTH / MICROTRIM

NUEVA CAPA ADITIVA: sourceAlignment[]
Se usa ANTES de sourceRanges finales cuando la frase está localizada pero el límite exacto cae dentro de un cue.

sourceAlignment item recomendado:
id
speaker
desiredText
sourceLiteral
cueIds[]
parentStartTc
parentEndTc
parentStart
parentEnd
timingStatus
requiresMicrotrim
startAnchor
endAnchor
parentCueText
notes

TIMING STATUS
cue_verified = el cue completo coincide con el fragmento solicitado.
cue_based = el fragmento está dentro de uno o varios cues.
word_aligned = word timestamps resueltos.
verified = aprobado contra audio/master.
editorial_planned = sólo tiempo del montaje.
unresolved = no localizado.

REGLA
sourceRanges[] para Cutter se crea sólo con límites finales confiables. Un parent cue que contiene texto extra NO debe fingirse como corte exacto sólo porque tiene start/end válidos.

MICROTRIM TASK
{
  alignmentId,
  parentStart,
  parentEnd,
  startAnchor,
  endAnchor,
  method: pending_word_alignment,
  approved: false
}

SOURCE CORRECTION
Si el plan dice una frase diferente al transcript, conservar ambos:
originalPlanText
correctedText/sourceLiteral
correctionReason

Nunca corregir silenciosamente.

02_CANON/04_LIENZO_PROJECTION_CONTRACT_R6_1.txt
==========================================================================================
ABRXOS R6.1 · CONTRATO DE PROYECCIÓN AL LIENZO

EL LIENZO NO REINTERPRETA LA FICHA. PROYECTA DATOS.

SELECCIONAR PIEZA
→ decide workspace por type.

VIDEO WORKSPACE
Story / transcript panel:
- parts en orden editorial;
- SOURCE vs VO claramente diferenciados;
- microtrim/source status visible.

Inspector contextual:
A-roll → source literal, parent cue, sourceRange/sourceAlignment, timing status.
VO → texto, placement, audio asset, measured duration.
XR → family, function, states, assets, prompts, placement, status.
Image/Object → descripción, prompt, search, continuity, status.
Motion → property/keyframes/easing.
CINE → cineType, visual, hold, music, silence, caption policy.
SFX → trigger/purpose/search/mix.
Music → automation segment.
Caption Group → sourceText, wordCount, highlight, displayCues, visibility/suppressedBy.

TIMELINE
Cada evento timeline[] se dibuja en lane por track.
XR parent en T2; children relacionados en T3/T4/T7.
CINE root en T5, no T10.
VO en T6.

GHOST / NEEDS REVIEW
Eventos editorial_planned o sourceAlignment no resuelto deben verse con estado visual needs_review/dashed. El Lienzo no debe presentarlos como source verified.

MOVIMIENTO
Click sólo selecciona.
Drag real cambia edit time.
No cambia sourceRange automáticamente.

PERSISTENCIA
Edición → state.project → autosave/export → app-data actualizado.

ABRXOS R6.1 · CAPTIONS Y COMPATIBILIDAD

POLÍTICA R6
T9 muestra Caption Groups, no microcajas por 3–5 palabras.
Target 8–15 palabras.
Soft 6–17.
HERO_WORD excepcional.
displayCues internos pueden mostrar 2–3 etapas sin multiplicar bloques T9.

CAMPOS
captionSchema: abrxos.caption.v2
captionPolicyVersion: R6
partId
routes
start/end
sourceText
wordCount
highlightWord
displayMode
visibility
suppressedBy
displayCues[]

COMIC_CC
No borrar captions. visibility=hidden + suppressedBy=XR_ID.

PATCH GEOMETRA
Si captionPolicyVersion=R6:
- NO ejecutar normalización legacy 3–5;
- mantener un block T9 por Caption Group;
- inspector abre displayCues;
- hidden se dibuja atenuado.

LEGACY
Piezas antiguas sin R6 pueden conservar su política anterior. No migrar destructivamente.

R6.1 CLARIFICATION · FUENTE COMPLETA < 6 PALABRAS
Si TODO el texto de la part tiene menos de 6 palabras, NO rellenar, NO mezclar con otra part y NO inventar texto para llegar al rango.
Se permite un Caption Group corto con:
shortSourceException=true
shortSourceReason="complete source part under soft range"

El validador R6.1 debe aceptar esta excepción sin warning si sourceText coincide con la totalidad de la part.

02_CANON/11_ROUTE_SEMANTICS_R6_1.txt
==========================================================================================
ABRXOS R6.1 · ROUTE SEMANTICS

ROUTE NO SIGNIFICA «TIPO DE AUDIO».
Una route es una ALTERNATIVA EDITORIAL COMPLETA.

Incorrecto:
source speech → routes:[source]
VO → routes:[voA]
si la intención es que ambos aparezcan juntos en el mismo montaje.
Eso haría que un renderer que filtra por route muestre uno u otro.

Correcto para este intro:
route final contiene SOURCE + VO + XR + recursos que forman el montaje aprobado.

Ejemplo:
P03 Amanda source routes:[final]
VO01 Narrador routes:[final]
P04 Amanda source routes:[final]

Si además se desea variante sin VO:
- crear route source_only con tiempos recalculados;
- source events pueden pertenecer a [final, source_only] sólo si sus edit times son compatibles;
- si los tiempos cambian al retirar VO, usar routeTimings separados o eventos derivados, no dejar huecos silenciosos por accidente.

Regla:
kind/sourceRole describe SOURCE_SPEECH vs VO_ADDED.
route describe una versión completa del montaje.
